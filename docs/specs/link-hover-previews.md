# Specification: Internal Link Hover Previews (Wikipedia / Gwern Style Popups)

## 1. Context & User Story
Readers browsing [arunsr.in](https://www.arunsr.in) frequently encounter internal links connecting ideas across tech notes, book reviews, game retrospectives, and research commentaries. Currently, opening these links requires opening new browser tabs or navigating away from the current note, disrupting reading flow.

As a reader exploring notes on arunsr.in, I want Wikipedia / Gwern style hover previews on internal links so that I can:
- Quickly inspect what an internal link discusses without leaving my place in the current note.
- See key metadata at a glance: title, category icon, reading time, tags, and opening excerpt.
- Seamlessly move my cursor into the preview card to read or dismiss it by moving away or pressing `Escape`.
- Have an undisturbed mobile experience where taps navigate directly without popup interference.

---

## 2. Author Decisions (Phase 1 Scoping)
During the Phase 1 interview and requirement review, the author confirmed:
1. **Target Scope (Option A)**: Previews apply strictly to prose links inside article content (`.content a:not(.external-link)` or `article .content a`). Navigation, breadcrumbs, sidebar tree, right TOC, tags, and footer links are strictly excluded.
2. **Mobile Behavior (Option A)**: Completely suppressed on touch-only devices (`@media (hover: none)`) so mobile readers experience standard single-tap navigation without popup delay or double-tap confusion.
3. **Excerpt Length**: 160–200 characters of clean, unformatted plain text.
4. **Data Source**: Uses `/index.json` (enhanced with `"readingTime": {{ $e.ReadingTime }}`) fetched lazily or upon first hover and cached in memory.

---

## 3. Core Guardrails (AGENTS.md Compliance)
- **Sacred Prose (Rule 9)**: No markdown prose or note text may be rewritten or altered.
- **Performance & Zero Bloat (Rule 1)**: Pure vanilla JavaScript (< 2.5KB), zero external dependencies or heavy tooltip libraries.
- **Cloudflare Rocket Loader Safety (Rule 2)**: ZERO inline event handlers (`onmouseenter`, `onmouseleave`, etc.). All event listeners attached unobtrusively via `addEventListener` after DOM load.
- **Visual Identity (Rule 1)**: Signature light-blue accent (`#0284c7` in light mode, `#38bdf8` in dark mode), subtle shadow, rounded corners, clean dark mode support.
- **Stacking Contexts (Rule 13)**: The preview card container is appended directly to `document.body` at a high z-index (`z-index: 1250`) so it is never trapped by layout containers.
- **Automated Regression Testing & CI Parity (Rules 10 & 11)**: Dedicated automated test suite in `scripts/` verifying DOM presence, link filtering, metadata rendering, Rocket Loader safety, and CI discovery parity.
- **Windows UTF-8 Stdout Reconfiguration (Rule 12)**: All companion Python test scripts must include standard UTF-8 stdout reconfiguration.
- **Minified HTML Assertion Robustness (Rule 14)**: Regex assertions must tolerate optional quotes generated by `hugo --minify`.

## 4. Numbered Acceptance Criteria

1. **Internal Content Link Targeting**:
   - Previews activate only for internal links situated within `.content a` (main article prose).
   - External links (`.external-link`, `target="_blank"`), anchor jump links (`#...`), and media/asset links (`.pdf`, `.png`, `.jpg`, `/static/`) are ignored.
   - Header links, navigation links, breadcrumb links, TOC links, and footer links do not trigger previews.

2. **Index Enhancement & Data Caching**:
   - `layouts/index.json` includes `"readingTime": {{ $e.ReadingTime }}`.
   - The index is fetched asynchronously on first hover (or idle) and cached in a module-level variable to prevent repeated network requests.
   - Link `href` paths are normalized (handling trailing slashes and relative paths) to resolve the matching entry in the index cache.

3. **Preview Card Content & Layout**:
   - Preview card renders:
     - Header row with section category badge (💻 Tech, 📚 Books, 🎮 Games, 🔬 Research, 📝 Posts, 📄 Note) and reading time pill (`⏱️ X min read`).
     - Note Title linking to the target permalink.
     - Optional tags pills if tags exist.
     - Clean text excerpt (160–200 characters) with icon shortcodes and markdown hashes stripped.

4. **Debounced Hover & Bridge Interaction**:
   - Hovering an eligible internal link triggers preview display after a 250ms debounce delay to avoid flicker during normal mouse sweeping.
   - The preview card stays open if the user moves the mouse onto the preview card itself.
   - Moving the mouse away from both the link and preview card dismisses the card with a 150ms buffer.

5. **Keyboard & Touch Handling**:
   - Pressing `Escape` immediately dismisses the active preview card.
   - Scrolling the window or clicking outside dismisses the preview card.
   - Touch-only devices (`@media (hover: none)`) do not render hover cards, allowing instantaneous tap navigation.

6. **Smart Viewport Clamping**:
   - Card is positioned floating adjacent to the hovered link (preferring below, flipping above if near the viewport bottom).
   - Horizontal and vertical positions are clamped using `getBoundingClientRect()` to ensure the card never overflows viewport edges.

7. **Zero Bloat & Cloudflare Safety**:
   - Implementation is under 2.5KB vanilla JS.
   - Zero inline event handlers in templates or dynamically rendered HTML.
   - `jq . public/index.json` and `./scripts/test.ps1` / `./scripts/test.sh` exit 0.
